# wysiwyg

**模型驱动**的 Markdown WYSIWYG 编辑器，以 Dioxus Native (Blitz) 组件形式提供。

`model::Doc`（块树）是唯一真相源，DOM 是纯派生：渲染后不再反向写回，Blitz
只承担只读渲染与排版查询。因此不需要 contenteditable，也不需要光标锚点 hack。

## 快速开始

```rust
use dioxus_native::prelude::*;
use wysiwyg::{parse_doc, Editor, Wysiwyg};

#[component]
fn App() -> Element {
    let editor = use_signal(|| Editor::new(parse_doc("# 标题\n\n正文")));

    rsx! {
        // 组件按父容器尺寸布局，容器需有明确高度
        div { style: "width:100%; height:100vh;",
            Wysiwyg { editor, font_size: Some(16) }
        }
    }
}
```

可运行的完整示例（编辑区 + 实时源码分屏）：

```bash
cargo run -p wysiwyg --example demo
```

## 模块

| 模块 | 职责 | GUI 依赖 |
| --- | --- | --- |
| `model` | 块树、`Pos` / `Sel` 逻辑坐标 | 无 |
| `md` | Markdown ↔ `Doc`（pulldown-cmark 解析 + 公式花括号遮蔽，自写 emit） | 无 |
| `edit` | 编辑命令（`Cmd` / `Move` / `TableCmd`）与 `Editor` 状态机 | 无 |
| `render` | `Doc` → HTML 字符串 | 无 |
| `reveal` | "就地展开源码"：选区显示 Markdown 分隔符、光标处公式显示 LaTeX | 无 |
| `preview` | 与编辑共用块树的语义 HTML 预览 | 无 |
| `math` | LaTeX → 自包含 SVG | 无 |
| `chem` | 预览专用的化学式 / 公式定界符归一 | 无 |
| `hl` | 代码块着色钩子（宿主按需注册） | 无 |
| `paste` | HTML 剪贴板 → 清洗 → Markdown | 无 |
| `dom_index` | `data-bid` → `NodeId` 的增量索引 | blitz-dom |
| `geom` | 点击 → `Pos`、`Pos` → 光标矩形的双向查询 | blitz-dom |
| `ui` | `Wysiwyg` 组件、事件接线、光标覆盖层 | dioxus-native |

前十个模块不含 GUI 依赖，可直接无头测试。

> `reveal` 是"就地展开源码"的唯一状态源：`render` 据此决定哪些节点输出 Markdown 分隔符，
> 编辑层据此判断某个公式 / 图片 alt 是否按文本编辑；`geom` 不需要它——虚拟字节由
> `data-vmark` 自描述。

## 就地展开源码（`reveal`）

编辑视图默认是"所见即所得"：`**粗体**` 显示为粗体、`$x^2$` 显示为排版好的公式。
但有两处需要看到源码本身：

| 触发 | 展开单位 | 效果 |
| --- | --- | --- |
| 框选**两个块及以上** | 每个被扫到的**整块** | 内联分隔符（`**`、`` ` ``、`[..](url)`、`$x$`、`![..](url)`）+ 块前缀（`#`、`-`/`1.`/`- [x]`、`> `、代码围栏、表格的 `|` 与分隔行、`---`）全部显示；内容仍保留原格式 |
| 光标落在一个公式内或左右两侧；或**选区停留在一个公式 / 图片 alt 内部** | 仅该原子 | SVG 换回 LaTeX 源码，光标可直接进入源码逐字编辑，整行其余部分保持排版态；选区不再落在"看不见的原文"上，删除只吃掉选中的那几个字符，而不是整个节点 |

**例外：`$$…$$` 独占一个块的显示公式不因光标而展开**。这种块里光标的全部位置就是公式自己的
两端（块首 / 块尾），展开等于让整块永久停在源码态：打开文档先看到裸 LaTeX、整块永远读不到，
`Home` / `End` 也会落到 LaTeX 的行首 / 行尾而不是块首 / 块尾（`"$$\n{a}\n$$"` 的源码有三行，
`End` 停在 `$$` 那一行）。它保持排版态，需要源码时用框选（块级展开照常）。

单位是"块"而不是"行"，也不是"节点"：只要框到**两个块**，哪怕只框住其中一个块的几个字，
这两个块也各自整体展开；**只框住一个块时什么都不展开**——哪怕这个块内部有软/硬换行
（一个段落写成多行仍然是一个块），哪怕框满了整块。在段落里选几个词是复制动作，不是要看源码。

两条规则共用一个机制（`Reveal`：一组块号 + 一个单独展开的原子）+ 一个约束：
**分隔符是"虚拟字节"**。

- 分隔符渲染成 `<span data-vmark="N">`：占 `N` 个排版字节，但**不占** plain 文本字节。
  `Pos.off` 始终等于 `Block::plain_text()` 的下标，所有编辑命令不受影响。
- 分隔符全部来自 `md`：`inline_delims`（内联）、`heading_marker`、`code_fence_lines`、
  列表标记与表格分隔行，与 `emit`（复制、保存、导出）用同一份规则表，因此"看到的"和
  "`Ctrl+C` 得到的"逐字节一致。
- `geom` 双向映射跳过虚拟字节：点击分隔符吸附到它所装饰的边界，光标在内容起点画在
  开分隔符**之后**（`$|x$`）、在内容末尾画在闭分隔符**之前**（`$x|$`）。
- 展开的公式源码是**真实文本**（`data-math` + `data-math-src`，不带 `data-vlen`），
  所以光标可以停在公式中间，输入 / 退格直接改 LaTeX；`math_at` 对这类节点让位给精确文本命中。
- 表格对读者是**一个块**：碰一下任意单元格，整张表的 `|` 与分隔行都出来，但 DOM 仍按单元格
  保留 `data-bid`，光标依旧按单元格寻址（表格是表格布局，管道符不可能像源码那样左对齐，
  这是唯一一处"看到的"与"复制的"空格不完全一致的地方）。
- **展开不改块高**：源码态复用排版态的盒子 —— 表格单元格保留同样的 padding 与边框**宽度**
  （边框透明而不是去掉），分隔行压成一行；再叠一层 `min-height`（按下时用
  `Geom::block_heights` 量下每个块的排版态高度，见 `render::set_height_floors`）。块只会因为
  "源码比排版态多出几行"（代码围栏、分隔行、`---`）而变高，绝不会塌陷 —— 塌陷会让下方文字
  上移、指针下的那一行换掉，这正是拖动时选到一半"跳"的来源。
- 被展开的行铺一层很淡的底色（`REVEAL_TINT`）：文本选区只盖住扫过的字符，整行都在源码态，
  底色让人看清这次扫描到底覆盖了哪些行。颜色取宿主注入的 `--wys-tint`（主题 accent 的 10%），
  亮/暗主题都成立；未设置时回落到浅色主题的蓝。
- 空白区（表格右侧、段间、文档末尾）的点击与拖拽都走同一套按行映射：落点是**指针所在那一行**
  的块首/块尾，而不是"二维上最近的文本"——后者会随着块变宽变窄而漂移。
- **展开是实时的**：拖拽过程中指针扫到哪个块，那个块立刻变成源码，不需要松开鼠标。
  为此拖拽选择由组件自己接管（见下），`Reveal` 每次从 `sel` 现算、从不缓存。
- 拖拽为什么必须自己接管：blitz 原生拖拽把按下时命中的 `NodeId` 当锚点，中途重建片段会让
  锚点悬空、拖拽直接失效。现在内容区 `user-select: none` 关掉原生拖拽，`onpointermove`
  每次都对**当前**布局重新求位置，所以块在指针下展开/收起都不会留下悬空引用
  （`cursor: text` 保住 I 形光标；拖拽期间浮动工具条隐藏，否则它会盖住指针并吞掉移动事件）。
- 拖拽用 `Geom::drag_pos_at` 而不是 `pos_at`：后者回答"离这个点最近的文本"，而展开会改变块的
  宽度（表格有边框时宽、源码态窄），于是同一个位置会在两个块之间来回映射 —— 表格就在排版态与
  源码态之间闪。`drag_pos_at` 先按**竖直带**选块（同级按水平距离取最近的，因此表格行取最后
  一格），指针超出该块右边界时一律取"块尾"：两种形态给出同一个答案，扫描不会来回翻转。
- 行内**公式在排版态是一个整体**：指针落在它的盒子里（整个行带，实测上下各多出 6px 也命中）
  时，光标一律停在**公式前沿**，也就是公式前最后一个元素之后；越过盒子才继续向前。盒子形状
  不变，答案就不会在盒子里来回跳 —— 而 `pos_at` 在这里必然要翻：公式盒子里没有文本节点，
  `find_text_position` 只能回答"最近的文本"，指针偏左取前一段的末尾、偏右取后一段的开头，
  这正是"拖到公式中间光标回退"的成因。已展开为源码的公式不在此列（那时它是真实文本，落在
  哪个字符就是哪个字符），排版失败退化成 `<code>` 的公式同样不在此列；整段只有一个公式的块
  也不在此列（display 公式由块级映射按 x 取首/尾）。


## 组件参数

| 参数 | 说明 |
| --- | --- |
| `editor: Signal<Editor>` | 必需；状态机由宿主持有 |
| `font_size: Option<i32>` | 正文字号，缺省 16 |
| `fg: Option<String>` | 内容前景色（暗色主题应传入，否则公式可能不可见） |
| `--wys-tint`（CSS 变量，宿主在根元素上设置） | 被展开行的底色；缺省 `rgba(74,125,255,.07)` |
| `img_base: Option<PathBuf>` | 相对图片的解析基准，通常是文档所在目录 |
| `on_open_link` | Ctrl+点击链接的回调 |
| `on_edit` / `on_caret` | 鼠标编辑 / 光标移动后的通知，宿主据此同步外部状态 |
| `on_ready` | 组件挂载后交出 `NodeHandle` |
| `overlays` | 与宿主共用的光标 / 单元格覆盖层状态 |
| `grab_focus: Option<bool>` | 是否自行抢焦点；接入既有编辑器时应为 `false` |

## 接入宿主的约定

1. 宿主设 `grab_focus = false`，组件也不设 `tabindex`——否则按键会绕过宿主的
   输入桥，状态不同步。
2. 每次编辑后，宿主把内容写回自己的文档模型。infeditor 的实现是
   `src/ui/components/mdws.rs::sync_to_doc`：幂等、最小差异替换，撤销粒度与
   编辑器内一致。
3. `parley` 必须与 blitz 解析到同一个 rev，否则 `Layout<TextBrush>` 类型不互通。
4. blitz 的 inline 排版使用物理像素，读取 parley 几何时要除以缩放比。
5. 渲染期间不能访问 Blitz 文档（此时已被可变借用）；几何计算放在事件处理器里，
   结果存进 Signal 供渲染读取。
